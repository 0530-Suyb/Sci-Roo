# Research Problem Framing Skill

## When to Use

- A project has a title or short description, but the actual research problem is still fuzzy
- The user wants help identifying the central question before designing experiments
- The team needs to turn background context into concrete research questions
- The paper plan feels premature because the problem statement is not yet stable

## When NOT to Use

- The research questions are already explicit and the next step is experiment design
- The main need is literature retrieval rather than problem clarification
- The user is already drafting a nearly complete manuscript section-by-section

## Core Principle

Always work in this order:

1. Project description and context
2. Research problem clarification
3. Research questions
4. Initial paper plan

Do not jump directly from description to paper outline.

## Dialogue Style

Use a Socratic, guided style:

- Ask 3-5 focused questions at a time
- Explain why each question matters
- Prefer narrowing questions over broad open-ended prompts
- Summarize what is now clear before asking the next round
- Stop and confirm if the framing changes substantially

The aim is not to impress the user with polished prose. The aim is to help the user discover the right problem definition.

## Clarification Sequence

### Step 1: Anchor the Context

From the project description, establish:

- What domain or application area is this work in?
- What phenomenon, task, or system is the work about?
- What practical or scientific pain point motivates the project?
- Who is affected by this problem?

### Step 2: Separate Topic from Problem

Check whether the current description is only:

- a topic
- a method idea
- a dataset idea
- a product goal

If so, push toward the actual unresolved problem:

- What is currently unsatisfactory?
- What remains unexplained or unsupported?
- What decision or understanding is blocked without this study?

### Step 3: Define Scope and Assumptions

Clarify:

- Intended setting or boundary conditions
- Core assumptions
- Out-of-scope cases
- What evidence might realistically be available

### Step 4: Formulate Research Questions

Produce questions that are:

- specific
- answerable
- aligned with feasible methods or evidence
- narrow enough to guide the study

Include:

- one primary research question
- optional secondary or supporting questions

### Step 5: Only Then Draft the Initial Paper Plan

Once the problem is stable, outline:

- working title direction
- core narrative arc
- likely section structure
- evidence or experiments still needed

Keep this lightweight. It is an initial plan, not a full manuscript.

## Required Outputs

The results should be suitable for:

- `problem/research-questions.md`
- `task/paper-plan.md`

Write the problem file first. The paper plan depends on it.

## Guardrails

- Never fabricate prior work, claims, or evidence
- Never treat a broad motivation as a finished research problem
- If ambiguity remains high, continue clarification instead of forcing a plan
- Distinguish clearly between what is known, what is assumed, and what needs to be tested
