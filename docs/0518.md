# 0518 开发总结

> 截至当前分支 `dev` 的实现总结，重点记录本阶段已经落地的科研工作流、ReadPaper 检索闭环、数据结构和前后端改动。

## 一、当前版本定位

本阶段的核心目标，是在 Sci-Roo 既有的科研模式体系上，补齐一条可复现、可审计、可回写的文献检索链路。

当前已经存在并继续沿用的科研模式包括：

- `sci-lit-review`
- `sci-hyp-design`
- `sci-data-analysis`
- `sci-visualization`
- `sci-paper-writing`
- `sci-peer-review`

在此基础上，本次新增了 `ReadPaper` 面板和对应的 retrieval 工作流，用来把“用户提出检索需求 -> 创建检索资产 -> 运行检索任务 -> 生成候选文献 -> 人工确认/排除 -> 归档”串成闭环。

## 二、本阶段已经完成的功能

- 新增 `ReadPaper` 入口与独立视图。
- 新增 retrieval 资产模型，存放检索任务、候选文献、检索摘要和回写状态。
- 新增 `RetrievalManager`，负责本地文件持久化、任务状态流转和活动日志写入。
- 新增检索提示词生成器 `retrievalAgentPrompt.ts`，把 agent 行为约束为严格 JSON 输出。
- 扩展 `search_literature` 工具，使其可直接作为 ReadPaper 检索任务的执行引擎。
- 扩展 webview 消息通道，支持创建、保存、运行、确认、排除、归档 retrieval。
- 增加 `.roo/activity_log.jsonl` 和 `.roo/literature/retrievals/` 作为检索资产存储区。

## 三、ReadPaper 工作流

ReadPaper 的主流程是：

1. 用户在面板里填写检索需求，包括标题、问题描述 `Q`、查询式 `query`、关键词、来源、年份范围和纳入/排除标准。
2. 前端把表单内容发给扩展后端，后端创建或更新一个 `retrieval_xxxx.json`。
3. 用户点击运行后，后端创建一个内部 agent task，任务名固定为 `ReadPaper Retrieval Task: retrieval_xxxx`。
4. agent 只能在 PubMed 和 arXiv 范围内做检索，并且必须返回严格 JSON。
5. 检索结果会被校验、去重、编号、截断并写回 retrieval 资产。
6. 用户可以对候选文献执行“确认/排除”，也可以对整个 retrieval 执行“确认/归档”。

这条链路强调三件事：

- 检索过程可复现。
- 检索结果可审计。
- 结果修改有明确状态流转，而不是一次性覆盖。

## 四、数据结构和存储

检索资产使用 `packages/types/src/retrieval.ts` 中的 Zod schema 统一约束，版本号为 `1.0`。

主要对象包括：

- `RetrievalTask`
- `RetrievalCandidate`
- `RetrievalListItem`
- `RetrievalSearchProvenance`
- `RetrievalResultSummary`
- `RetrievalAgentTask`

当前存储布局为：

```text
.roo/
  activity_log.jsonl
  literature/
    retrievals/
      retrieval_list.json
      retrieval_0001.json
      retrieval_0002.json
      ...
```

其中：

- `retrieval_list.json` 是索引。
- 每个 `retrieval_xxxx.json` 保存一个完整检索任务。
- `activity_log.jsonl` 记录创建、运行、回写、确认、排除、归档等事件。

当前 retrieval 的状态设计是：

- retrieval 状态：`未确认`、`已确认`、`已归档`
- candidate 状态：`候选`、`已确认`、`已排除`、`冲突`、`错误`

另外，候选文献有硬限制：

- 最多保留 200 条
- agent 提供的 `retrieval_no` 和 `candidate_no` 不作为可信来源，最终由插件统一编号

## 五、后端实现

### 1. `RetrievalManager`

`src/services/literature/RetrievalManager.ts` 是这次改动的核心。

它负责：

- 初始化工作区下的检索目录
- 读取和写入 retrieval 文件
- 创建、更新、运行 retrieval
- 接收 agent completion 或工具结果并回写
- 更新 candidate 状态
- 确认/归档 retrieval
- 写入活动日志

### 2. 任务执行

`runRetrieval()` 会：

- 校验 query/Q 和 source 是否可执行
- 把 retrieval 标记为 `running`
- 生成内部 prompt
- 创建一个非交互式 task
- 限制大部分工具，只保留检索所需能力
- 记录 taskId、prompt hash 和摘要信息

### 3. 结果回写

回写逻辑支持两条路径：

- agent completion 里直接返回 JSON
- `search_literature` 工具执行后的结构化结果

写回时会做这些处理：

- 用 Zod 校验结构
- 忽略 agent 自己写的 id
- 按 DOI / PMID / arXiv ID / 标题做去重
- 重新分配 candidate 编号
- 超过 200 条时截断并记错误
- 补全 provenance、summary 和状态字段

### 4. 失败处理

如果 completion 缺失、JSON 无效、任务中断或检索失败，系统不会静默丢数据，而是：

- 保留 draft retrieval
- 把错误写进 `result_summary.errors`
- 记录 `last_error_at`
- 写入活动日志

## 六、检索提示词

`src/services/literature/retrievalAgentPrompt.ts` 提供了统一的检索 prompt。

它明确约束 agent：

- 只允许使用 PubMed 和 arXiv
- 不允许做 PDF 下载、库导入、网页泛搜或文献综述式扩写
- 不允许问用户澄清问题
- 必须输出严格 JSON
- 必须记录实际 query 和 provenance
- 如果没有结果，只能以空候选并说明原因的方式返回

这一步的意义是把检索行为固定成可复用的协议，而不是依赖模型自由发挥。

## 七、`search_literature` 工具改造

`search_literature` 现在不只是一个普通检索工具，它已经和 ReadPaper 的 retrieval 资产联动。

当前工具能力包括：

- 接收 `query`
- 接收 `sources`
- 接收 `maxResults`
- 接收 `yearFrom` / `yearTo`
- 分别检索 PubMed 和 arXiv
- 返回结构化的 `search_provenance`、`result_summary` 和 `candidates`

并且在 ReadPaper task 场景下：

- 工具结果会被自动应用到对应 retrieval
- 不需要再手工复制结果
- task 完成时还会检查 completion result，作为补充或兜底

## 八、前端实现

### 1. 视图挂载

`webview-ui/src/App.tsx` 已经加入 `readPaper` tab，并挂载 `ReadPaperView`。

`src/activate/registerCommands.ts` 和 `src/package.json` 也增加了对应命令与顶部按钮入口。

### 2. 状态传输

`webview-ui/src/context/ExtensionStateContext.tsx` 新增了 `readPaperRetrievalState`。

后端通过 `readPaperRetrievalState` 消息把 retrieval 列表、当前选中项和错误状态推给前端。

### 3. 面板交互

`webview-ui/src/components/read-paper/ReadPaperView.tsx` 负责：

- 读取当前 retrieval 状态
- 缓存表单输入
- 创建 retrieval
- 保存 retrieval
- 运行 retrieval
- 切换 retrieval
- 确认/排除 candidate
- 展示 provenance、summary、错误和候选列表

这里的表单状态是本地缓存的，不直接绑到后端状态，避免编辑时被异步刷新覆盖。

## 十、当前边界

当前版本仍然刻意不做这些内容：

- `library.json` 的正式文献库导入
- PDF 下载
- PDF 解析和 chunk 化
- 跨 retrieval 去重
- Google Scholar、Semantic Scholar、Crossref 等更广泛来源
- 自动筛选 inclusion / exclusion
- 在 retrieval 资产里保存完整 agent 对话

也就是说，这一版的定位仍然是“检索资产和候选池”，不是完整文献管理器。
