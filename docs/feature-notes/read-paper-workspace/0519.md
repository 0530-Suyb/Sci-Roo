# 2026-05-19 阶段记录

> 这是一份历史开发记录，用来说明 2026-05-19 这一天团队当时准备推进什么、为什么这样排优先级。  
> 它不是当前版本的产品说明，也不应替代根目录下的 `README` 系列文档。

## 本阶段关注点

这一阶段的核心目标，是把 Sci-Roo 从“分散功能集合”继续推向一个可演示、可验证的科研工作流原型，重点围绕下面三条主线展开：

1. 打通 `读文献 -> 写论文 -> 做实验` 的最小可信闭环。
2. 明确 Magazine/Survey 类型综述写作所需的 AI 能力边界。
3. 同步补齐资产设计和文档体系，避免只有功能、没有方法论。

## 当时计划推进的重点工作

### 1. Magazine 综述 MVP 能力拆解

当时的一个重要判断是：如果要做出可展示的科研 AI 产品，不应只看“能不能检索文献”，而要看能不能支撑一篇综述型成果的形成。因此，当时优先梳理了这类能力：

- 文献检索与候选收集
- 文献库入库与管理
- 单篇与批量文献分析
- 综述大纲生成
- 段落撰写与结构润色
- 引用整合
- 问题拆解与实验建议

这部分后来直接影响了 `Read Paper Workspace`、`Paper Writing Workspace` 和 `Research Pipeline` 的分工方式。

### 2. ReadPaper 检索闭环继续补强

这一阶段对 `ReadPaper` 的预期已经不再是“单页检索表单”，而是一个可配置、可追踪的 retrieval workspace。计划重点包括：

- 完善 retrieval 配置和 defaults
- 提升候选摘要展示质量
- 补足候选确认、排除、入库等动作
- 扩展 scholarly source 范围
- 保留人工审核节点，避免 AI 直接覆盖资产

后续落地中，`ReadPaper` 逐步演化成了今天的 retrieval session + library/map draft + settings 的 workspace shell。

### 3. 资产层设计统一

当时已经明确意识到，科研工作区不能只围绕“界面功能”设计，还必须围绕资产流转设计。因此这个阶段把重点放在：

- 文献资产
- 问题资产
- 文本块与证据卡片
- 实验记录
- 写作材料

这类资产的创建、引用、更新、回写和归档关系，后来也成为 `Research Pipeline` 作为总控入口的重要基础。

### 4. 文档补齐与可交接性

这一天的另一个重点，是不再只做功能开发，而是同步输出方案文档和流程说明。背后的原因很直接：

- 功能越来越多，必须有文档才能维护
- 需要把产品思路和实现思路分层
- 后续 Demo、评审和协作都需要一套可解释材料

## 当时的验收思路

这个阶段更看重“能否支撑最小科研闭环”，而不是单点功能是否华丽。当时设想的最小闭环包括：

1. 用户提出一个综述主题。
2. 系统检索并收集候选文献。
3. 文献写入可管理的资产目录。
4. 形成结构化摘要或文献矩阵。
5. 生成综述大纲和初稿。
6. 给出实验设计建议。
