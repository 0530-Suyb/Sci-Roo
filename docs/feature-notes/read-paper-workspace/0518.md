# 2026-05-18 阶段记录

> 角色：历史开发记录  
> 用途：记录 `Read Paper` 相关能力在这一阶段的落地情况  
> 注意：这不是当前产品的最终用户说明，当前使用方式应以根目录各 README 为准

## 本阶段的核心目标

这一阶段的重点，是给 Sci-Roo 补上一条更可复现、可追踪、可审计的文献检索链路，让 `Read Paper` 不再只是一个零散的搜索入口，而是一个能留下 retrieval 资产的工作区。

核心目标包括：

- 引入 `Read Paper` 独立入口
- 建立 retrieval 资产模型
- 让检索结果可以保存、筛选和回看
- 把候选文献筛选流程变成一个明确的状态流

## 当时已完成的关键工作

### 1. Read Paper 工作区初步成形

本阶段已经把 `Read Paper` 做成了独立工作区，而不是普通按钮或临时界面。

它能承担：

- 创建 retrieval
- 保存 retrieval
- 运行 retrieval
- 展示候选文献
- 确认 / 排除候选文献

### 2. retrieval 资产模型建立

这一阶段已经引入 retrieval 相关的数据结构和持久化模型，包括：

- retrieval 列表
- retrieval 详情
- candidate
- provenance
- result summary

目标是让一次检索不再只是即时结果，而是一个可保存、可追踪、可复用的资产。

### 3. RetrievalManager 落地

这一阶段后端已经形成了 `RetrievalManager`，用来承担：

- retrieval 文件读写
- 状态更新
- activity log 写入
- 结果回写

### 4. 检索链路打通

这一阶段已经打通了从：

- 用户提出检索需求
- 创建 retrieval
- 运行检索
- 获取候选结果
- 回写 retrieval

这一整条主链路。

### 5. 前后端消息通道接通

这一阶段已经接入了 Read Paper 所需的消息通道，支持：

- retrieval 创建
- retrieval 保存
- retrieval 运行
- candidate 状态更新
- retrieval 确认 / 归档

## 本阶段的产品意义

这一阶段真正带来的变化不是“多了一个检索页”，而是：

- 文献检索开始拥有明确资产形态
- 候选筛选不再依赖一次性搜索结果
- 后续可以围绕 retrieval 继续扩展 library、map、import 等能力

## 当时仍然没有解决的事情

这一阶段仍然有明显边界，主要包括：

- 还不是完整文献管理器
- 还没有形成成熟的 library 工作流
- 还没有完整覆盖更多学术来源
- 还缺更正式的用户文档
