# ReadPaper Retrieval Plan

## Goal

Implement the first ReadPaper literature retrieval workflow as reproducible retrieval assets. The user enters a natural-language retrieval request in the ReadPaper panel, starts a retrieval, and Sci-Roo creates a `retrieval_x.json` asset. An agent task performs the actual PubMed/arXiv search and must return strict structured JSON. The extension validates that output and automatically writes it back to the retrieval asset.

## Scope

Included in v1:

- Create and update retrieval assets.
- Execute retrieval through the existing agent/tool/MCP task flow.
- Allow only PubMed and arXiv as retrieval sources.
- Store candidates inline inside `retrieval_x.json`.
- Validate agent output with Zod before writing candidates.
- Deduplicate candidates within the current retrieval only.
- Truncate saved candidates to 200.
- Record retrieval provenance and activity log entries.
- Let users confirm/exclude candidates and confirm/archive retrievals.

Excluded in v1:

- `library.json`.
- Literature import / paper library.
- `papers/`, `paperlist.json`, and `paper_x/paper.json`.
- PDF download.
- PDF parsing and `chunks.json`.
- Structured summaries.
- Google Scholar, Semantic Scholar, Crossref, or broad web search.
- Cross-retrieval deduplication.
- Automatic inclusion/exclusion screening.
- Full agent conversation persistence inside retrieval assets.

## Asset Layout

All retrieval assets live in the current workspace:

```text
.roo/
  activity_log.jsonl
  literature/
    retrievals/
      retrieval_list.json
      retrieval_0001.json
      retrieval_0002.json
```

`retrieval_list.json` is an index. Each `retrieval_x.json` stores the full retrieval task and inline candidate records.

## States

Retrieval states:

```text
未确认 / 已确认 / 已归档
```

Candidate states:

```text
候选 / 已确认 / 已排除 / 冲突 / 错误
```

Candidate confirmation does not automatically confirm the retrieval. Retrieval completion is a separate user action.

## Numbering

Retrieval ids are plugin-generated and strictly increasing:

```text
retrieval_0001
retrieval_0002
```

Candidate ids are also plugin-generated after validation:

```text
candidate_0001
candidate_0002
```

Agent-provided `retrieval_no` and `candidate_no` are not trusted.

## Agent Workflow

The ReadPaper panel starts a clear system task:

```text
ReadPaper Retrieval Task: retrieval_0001
```

The task prompt is generated by an internal prompt builder. The prompt constrains the agent to:

- Use only PubMed and arXiv.
- Use the existing tool/MCP flow.
- Return strict JSON only.
- Return candidates only, not included papers.
- Avoid BibTeX, PRISMA, narrative synthesis, PDF work, or library import.
- Never fabricate references.
- Record actual queries and search provenance.
- Emit empty candidates only with provenance and `no_results_found`.

## Automatic Write-Back

The extension records pending retrieval runs by task id. When the task completes:

1. Find the last `completion_result` message for that task.
2. Extract JSON from the completion result.
3. Parse and validate it with Zod.
4. Normalize allowed sources and fields.
5. Ignore agent-provided retrieval/candidate ids.
6. Deduplicate candidates within this retrieval.
7. Truncate to 200 candidates.
8. Update `retrieval_x.json`.
9. Update `retrieval_list.json`.
10. Append `.roo/activity_log.jsonl`.
11. Refresh the ReadPaper panel.

If the agent fails or returns invalid output, the retrieval draft is preserved and the error is written to `result_summary.errors`.

## Validation Rules

- `query` is required for execution, but drafts may be saved without it.
- At least one source is required for execution.
- `Q` is optional but should be shown as recommended in the UI.
- Only PubMed/arXiv candidates are saved.
- Source failure does not fail the full retrieval.
- Empty candidates are allowed only with provenance and an error such as `no_results_found`.
- Full raw API responses are not saved.

## Activity Log

`RetrievalManager` writes `.roo/activity_log.jsonl` directly in v1. Events include:

```text
create_retrieval
update_retrieval
run_retrieval
agent_output_applied
agent_output_invalid
confirm_candidate
exclude_candidate
confirm_retrieval
archive_retrieval
```

## Implementation Slices

1. Add retrieval types and Zod schemas.
2. Add `RetrievalManager` with file persistence and activity logging.
3. Add internal `retrievalAgentPrompt` builder.
4. Add webview messages and handlers for ReadPaper retrievals.
5. Update `ReadPaperView` UI.
6. Start a system agent task from ReadPaper.
7. Capture task completion and automatically write back agent output.
8. Add focused tests and run type/build checks.
